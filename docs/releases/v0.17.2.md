# ChopLab v0.17.2

This patch carries the merged Windows CHOP long-press and ownership repairs forward while correcting two release-blocking toolchain boundaries discovered after the immutable `v0.17.1` tag was created. No `v0.17.1` Release was published, and that tag is not moved or replaced.

## Highlights

- Assigned CHOP PAD long-press preserves its existing START/END range, auditions without destructive recapture while the source is stopped, and opens the fitted TRIM view.
- LOOP, GATE, PREVIEW, recoverable output failure, and exact voice-ownership repairs from the merged `v0.17.1` source remain unchanged.
- Android framework accessibility checks wait for the complete S/E/chop-marker tree before asserting order, focus, and custom actions.
- Desktop offscreen input reacquires a finite, in-viewport semantics target immediately before each mouse gesture and keeps full failure stacks.
- Compose Multiplatform is pinned to the previously verified 1.11.1 line because 1.12.0 repeatedly corrupted its offscreen `RectManager` during both scene close and a later render. No Compose exception is filtered or ignored.
- Android signing verification now requests the signer certificate in PEM form, computes SHA-256 from its DER bytes, and cross-checks any textual `apksigner` digest. Missing, malformed, multiple, or conflicting certificate evidence fails closed.
- Embedded Gradle and XcodeGen identity is `0.17.2 (29)`.

## Validation boundary

Local verification includes the 24-test H13 Desktop target, 180 full Desktop tests, Windows `installDist`, AndroidTest Kotlin compilation, release-policy tests, public-surface scanning, and PEM-backed verification of a generated debug APK. The tag workflow must rebuild and verify Android, iOS, Windows, SBOM, checksums, manifest, and attestations from the exact merged commit before it creates the public Release.

## Distribution boundary

The public Release may contain only the explicitly verified Android debug preview, unsigned iOS Simulator archive, SBOM, manifest, checksums, and sidecars. The stable-signed Android candidate and Windows app-image are verification-only. No Spotify content, user audio, credentials, recordings, MP3 conversion, or downloaded media are included. Physical-device audio, Windows driver quality/latency, screen-reader speech, Spotify provider behavior, signed iOS device distribution, and human acceptance remain separate gates.
