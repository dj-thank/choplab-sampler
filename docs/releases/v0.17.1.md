# ChopLab v0.17.1

This patch makes the existing long-press precision-trim flow reliable on Windows while retaining the Android-origin Chop workflow.

## Highlights

- Holding an assigned CHOP PAD while the source is stopped now auditions the existing Chop and opens TRIM without overwriting its START/END range first.
- A stopped empty PAD still only becomes selected, while source playback still captures the observed source position into the selected Chop.
- Recording, source-transition, and project-loading ownership continue to block destructive PAD edits with the existing Japanese guidance.
- Persisted LOOP PADs now use the managed loop-session transaction instead of an untracked raw voice.
- GATE auditions retain their exact pointer-down ownership, so a delayed mouse release cannot stop a newer keyboard voice; a failed audition also cannot arm a later broad release.
- Recoverable output startup failures are reported without cancelling the long-press gesture, so TRIM remains available even when no playback line can be opened. Fatal errors still propagate.
- A dedicated offscreen Desktop Compose input suite drives the real shared deck and controller with mouse press/release events. It covers assigned and empty PADs, source playback, both waveform edges, short-click behavior, and recording/import guards.
- Both the Windows pull-request workflow and immutable Release workflow run that dedicated input suite before packaging, so the regression cannot be hidden by the default headless-test exclusion.
- The release advances Gradle and XcodeGen defaults to the same embedded identity, `0.17.1 (28)`; the immutable `v0.17.0` tag and assets are not changed.

## Validation boundary

The original H13 component candidate passed 14 focused tests: 9 real Compose input tests and 5 controller tests. PR review added six negative-path regressions for managed LOOP, GATE ownership, output failure, fatal propagation, and generated iOS metadata; the current dedicated target contains 20 tests (10 Compose input / 10 controller). A source-bound local Windows `0.17.0` app-image was also packaged and launched in an isolated profile before this integration; those H16/H19 receipts prove only the older exact candidate bytes and are retained separately for provenance. The `v0.17.1` Android, Windows, and iOS artifacts must be rebuilt and verified by the tag workflow from the merged release commit.

## Distribution boundary

The Windows asset remains a self-contained unsigned app-image preview, not a code-signed MSI/MSIX. No Spotify content, user audio, credentials, recordings, or converted media are included. Physical-device audio, Windows driver latency/audio quality, screen-reader speech, Spotify provider behavior, signed iOS device distribution, and human acceptance remain separate verification gates.
