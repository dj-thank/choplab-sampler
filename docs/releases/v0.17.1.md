# ChopLab v0.17.1

This patch makes the existing long-press precision-trim flow reliable on Windows while retaining the Android-origin Chop workflow.

## Highlights

- Holding an assigned CHOP PAD while the source is stopped now auditions the existing Chop and opens TRIM without overwriting its START/END range first.
- A stopped empty PAD still only becomes selected, while source playback still captures the observed source position into the selected Chop.
- Recording, source-transition, and project-loading ownership continue to block destructive PAD edits with the existing Japanese guidance.
- Persisted LOOP PADs now use the managed loop-session transaction instead of an untracked raw voice.
- GATE auditions retain their exact pointer-down ownership, so a delayed mouse release cannot stop a newer keyboard voice; a failed audition also cannot arm a later broad release.
- Narrator/semantics GATE activation uses the same owned capture route and a bounded 80 ms audition; rapid activations release only their own voices.
- Recoverable output startup failures are reported without cancelling the long-press gesture, so TRIM remains available even when no playback line can be opened. Fatal errors still propagate.
- TRIM PREVIEW always uses one bounded ONE_SHOT voice even when the saved PAD mode is LOOP.
- If a replacement voice starts but retirement of an older voice fails, Java Sound abandons the new candidate before surfacing the failure and retains failed cleanup ownership for later stop retry.
- A dedicated offscreen Desktop Compose input suite drives the real shared deck and controller with mouse press/release events. It covers assigned and empty PADs, source playback, both waveform edges, short-click behavior, and recording/import guards.
- Both the Windows pull-request workflow and immutable Release workflow run that dedicated input suite before packaging, so the regression cannot be hidden by the default headless-test exclusion.
- The release advances Gradle and XcodeGen defaults to the same embedded identity, `0.17.1 (28)`; the immutable `v0.17.0` tag and assets are not changed.

## Validation boundary

The original H13 component candidate passed 14 focused tests: 9 real Compose input tests and 5 controller tests. Two review rounds added negative-path regressions for managed LOOP, bounded PREVIEW, physical/semantics GATE ownership, output and post-start retirement failure, fatal propagation, and generated iOS metadata. The current dedicated target contains 24 tests (12 Compose input / 12 controller), with the Java Sound retirement cleanup covered in its engine suite. A source-bound local Windows `0.17.0` app-image was also packaged and launched in an isolated profile before this integration; those H16/H19 receipts prove only the older exact candidate bytes and are retained separately for provenance. The tag workflow must rebuild and verify Android, iOS, and Windows from the merged commit; only the Android and iOS preview files enter the public Release.

## Distribution boundary

The Windows app-image remains an unsigned verification artifact, not a public Release asset or code-signed MSI/MSIX. No Spotify content, user audio, credentials, recordings, or converted media are included. Physical-device audio, Windows driver latency/audio quality, screen-reader speech, Spotify provider behavior, signed iOS device distribution, and human acceptance remain separate verification gates.
