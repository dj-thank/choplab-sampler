## Android Bluetooth connection

After building this candidate, open **DDJ-200** above the deck:

1. Power DDJ-200 through USB. Disconnect it from other DJ apps.
2. Choose **Bluetoothで接続する**. Allow Nearby devices on Android 12+;
   Android 10/11 also requires foreground location permission and location ON.
   The app does not collect location or persist Bluetooth addresses.
3. Accept the Android Bluetooth-enable prompt if needed, then select DDJ-200
   from the app's list. This uses Android BLE MIDI, not ordinary audio pairing.
4. Press a populated PAD and check the connection/input counter. Closing only
   the dialog keeps the connection. Backgrounding/disposal disconnects and
   stops playback; reconnect explicitly on return.

Search is limited to 10 seconds and opening to 12 seconds. Standard discovery
uses ORed BLE MIDI service/name filters; **見つからない場合の追加検索（10秒）**
performs an explicit unfiltered scan but still accepts only DDJ-200 names.
Batch scan results, Bluetooth OFF, permission denial/revocation, stale callbacks,
queue overflow and MIDI errors are handled. Settings shortcuts cover permission,
Bluetooth and legacy location settings. USB remains an optional separate path.
No discovery, permission prompt or MIDI service lookup occurs at app startup.

**Bluetooth transports controller messages, not DDJ-200 audio.** Audio comes
from Android's selected output. Wireless audio latency is not measured here.

## Sampler and mixer controls

| DDJ-200 | Otohiroi |
| --- | --- |
| Left/right PADs | Current BANK's 1–8 / 9–16 |
| SHIFT + left/right PADs | Current BANK's 17–24 / 25–32 |
| Left/right SYNC | Previous/next BANK A–D |
| SHIFT + SYNC | Undo/Redo |
| Left/right PLAY | Source playback / BEAT transport |
| CUE or SHIFT + PLAY | ALL STOP |
| SHIFT + CUE | Existing step-record arm action |
| Left/right jog top | Source-range / selected-PAD scratch |
| Left/right TEMPO | Source pitch ±12 semitones / BPM 40–240 |
| Left/right CH faders | Left/right live audio group gain |
| Crossfader | Mix left/right live groups |
| LOW/MID/HI | Separate three-band EQ for each live group |
| Headphone CUE (left/right/master) | Select the split-output monitor mix |
| COLOR FX | Last-pressed PAD's saved TONE, existing behavior |

In each BANK, PADs 1–8 and 17–24 belong to the left group; 9–16 and 25–32
belong to the right. Source playback/preview belongs to the left group. PAD
voices, BEAT playback and selected-PAD scratch use the same group assignment.
This is a sampler with two mix groups, NOT two independent DJ playback decks.
The existing scratch engine remains shared; simultaneous touch/hardware scratch
and physical jog calibration are unverified.

Crossfader center leaves both groups at unity, endpoints mute the opposite group.
EQ uses broad LOW/MID/HIGH bands (250 Hz / 4 kHz one-pole decomposition), center
0 dB, extremes −26/+6 dB. It is not an emulation of Pioneer mixer DSP. Channel,
crossfader and EQ targets are smoothed; the existing master limiter is retained.
Move hardware through the current software value to engage soft takeover.
CH faders no longer change saved PAD gain; COLOR FX still edits saved PAD TONE.

**Mixer/EQ/cue are live-monitor settings only.** They are not saved to projects
or printed into exported WAVs. Disconnect resets the monitor settings and
stops playback. With the controller disconnected the old stereo mix path remains.

## Headphone split output

Use the DDJ-compatible DJ split cable: Android stereo LEFT goes to the speaker,
RIGHT goes to headphones. Each is mono. A standard identical-output Y cable
cannot separate them. A USB-C stereo audio adapter may be needed on the phone.

Connect/select a wired stereo output, play once so AudioTrack reports its actual
route, then choose **ヘッドホン分離を設定**. Confirm the physical splitter and
low-volume left/right test. Enabling/disabling split deliberately stops playback;
restart it afterward. CUE is post-EQ, pre-channel/crossfader; MASTER CUE uses the
post-fader master mix. With no CUE selected the headphone channel is silent.

The gate uses the actual AudioTrack route, NOT merely a plugged/paired device.
Speaker, wireless, multiple/unknown routes and declared mono-only outputs are
rejected. An endpoint with unspecified channel counts still requires physical
confirmation. A reported device change revokes split mode and stops playback.
Android notification delay and already-buffered audio remain physical test risks;
this is not a guarantee of zero unintended output during unplugging.

## LED feedback

Open the device's MIDI INPUT port for app-to-controller messages, independently
of the OUTPUT port receiving controller input. Send assignment/transport/record/
headphone-CUE state using the official note mapping. PAD lamps indicate assigned
slots in the current BANK, NOT actual sounding voices. Full snapshots are
conflated; one IO worker derives deltas after conflation and sends bounded
96-byte chunks. No output work runs on the audio callback. A missing/failed LED
port is reported without disabling controller input. Hardware acknowledgement,
actual lamps and Bluetooth throughput remain unverified. No all-lights-off
claim is made for abrupt disconnect.

## Architecture and tests

- `Ddj200.kt`: streaming MIDI parser, official profile, pickup and held-note tokens.
- `DdjMixer.kt`: independent mixer parser and allocation-free per-frame DSP.
- `DdjLedFeedback.kt`: cached state-to-MIDI messages.
- `AndroidDdj200.kt`: bounded input queue (32 × 4096 bytes), connection epochs,
  platform BLE MIDI, permissions, timeouts and independent LED worker.
- `AndroidDdjPerformance.kt`: immutable volatile per-block state and owner leases.
- `AndroidDdjAudioRoute.kt`: actual AudioTrack route notifications off audio thread.
- `SamplerEngine.kt`: stable source/PAD grouping before the existing master limiter.
- `Ddj200Controls.kt`: explicit connection, status, settings and split confirmation.

32 parser/session tests, 28 mixer tests, 6 LED tests and 8 pure owner/route tests
pass in the supplemental host runner. Production sources are unchanged by the
runner; temporary test copies adapt annotations/imports to available Kotlin CLI.

## Primary specifications

- AlphaTheta DDJ-200 MIDI Message List E2 (official table inspected):
  https://downloads.support.alphatheta.com/software_info/dj-controllers/DDJ-200/DDJ-200_MIDI_Message_List_E2.pdf
- Android MidiManager:
  https://developer.android.com/reference/android/media/midi/MidiManager
- Android BLE permissions:
  https://developer.android.com/develop/connectivity/bluetooth/bt-permissions
- Android AudioRouting (actual routed device list):
  https://developer.android.com/reference/android/media/AudioRouting
- AlphaTheta split output wiring:
  https://support.alphatheta.com/ja/articles/26320349269273

Deck channels are 0/1, crossfader channel 6 in zero-based MIDI bytes. EQ HI uses
CC 07/27, MID 0B/2B, LOW 0F/2F; CH fader 13/33; crossfader 1F/3F. These are
fresh MSB/LSB pairs, not independently applied 7-bit approximations. Normal PAD
channels are 7/9, shifted 8/10. CUE notes: decks 54/68, master channel 6 63/78.
